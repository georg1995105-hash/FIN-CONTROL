# Архитектура — исходное решение

Нативный Android (Kotlin, Compose), чистое JVM-ядро финансовых проверок без Android-зависимостей. Это выбранное инженерное направление, не результат готовой реализации. Android-версии и зависимости закрепить после проверки совместимости.

Поток: камера/импорт → подготовка изображения → локальный OCR/детектор → структурированные наблюдения с происхождением и уверенностью → проверка полноты/подтверждение → детерминированные правила → объяснимый результат → локальная история/экспорт.

Финансовое ядро: BigDecimal либо целые копейки, явное округление для дробных количеств, единая валюта в рамках проверки, отдельные скидки/налоги/авансы без повторного учёта, неизвестный режим округления/налога — запрос подтверждения. Не извлекать цены из внешних источников. Сравнение документов по подтверждённым позициям. Суммы расхождений не считать фактическими потерями.

Зрение: сначала эксперимент локального OCR русского языка и цифр, затем подсчёт по эталону и сравнение фото с проверкой качества/ракурса. Подмена, произвольные объекты, измерения — не обещать без измерений качества. Выбор модели после тестирования, проверки лицензии для коммерческого использования, размера, задержки и пикового RAM. Не загружать пользовательские фото в интернет.

Хранение: локальные записи и источники с явным управлением сроком хранения, системные разрешения только по необходимости, экспорт/импорт с проверкой формата и целостности. Для финансового анализа не требуется интернет. Платежи изолированы: серверная верификация оплаты, идемпотентность, подписанная лицензия, offline-проверка открытым ключом; секреты только на сервере. Не добавлять постоянную инфраструктуру до проверки необходимости.

## Этапы
0. Зафиксировать дизайн и требования.
1. Реализовать и протестировать ядро расчётов на структурированных данных; отдельно доказать качество OCR и компьютерного зрения на открытых или синтетических наборах. Метрики: точность денежных полей, доля корректных отказов, ложные расхождения, абсолютная ошибка подсчёта, задержка и RAM. Порог выпуска определяется после базовой оценки, ошибки критических денежных полей не скрывать.
2. Нативная оболочка по эталону, реальный импорт/камера, интеграция проверенных локальных технологий, история и отчёты.
3. Расширенные проверки документов и комплектности, UX, темы, резервное копирование, регрессии.
4. Проба, ЮKassa, лицензирование, тестовый платёж и восстановление; проверить правила магазина и налоговый контур.
5. Подписанный release, проверка на устройствах, офлайн, обновление и официальная публикация. Не выдавать промежуточный прототип за продукт.
