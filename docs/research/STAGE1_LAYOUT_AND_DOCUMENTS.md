# Этап 1 — расширение финансового ядра и проверка переноса алгоритмов, 26.11.2026

## Финансовый код
DocumentAudit сравнивает подтверждённые полные документы в RUB по заранее сопоставленным ключам позиций и одинаковой базе цен; обнаруживает добавления, удаления и изменения цены/количества. Не угадывает соответствие строк, не делает вывод о неправомерности изменений. Дубликаты ключей, конфликт единиц, неоднозначная база цен и некорректные данные требуют уточнения. Balance проверяет остаток после отдельно подтверждённого аванса; возвраты и кредитовые остатки пока не поддерживаются. Не заменяет проверку всех строк счёта.

Локально компилировались четыре Kotlin-файла: ReceiptAudit.kt, ReceiptAuditTest.kt, DocumentAudit.kt, DocumentAuditTest.kt. Команды: kotlinc core/src/main/kotlin/fincontrol/core/*.kt core/src/test/kotlin/fincontrol/core/*.kt -include-runtime -d /tmp/fin-tests.jar; java -cp /tmp/fin-tests.jar fincontrol.core.ReceiptAuditTestKt; java -cp /tmp/fin-tests.jar fincontrol.core.DocumentAuditTestKt. Результат: 18/18 прежних и 24/24 новых сценария PASS. Git blob SHA новых протестированных файлов: 92e171beb416f4f9589a06ba4229afa1e7a98630, b560cb896a482cb013bcb4677869d5bb8f2098ce.

## OCR — отрицательный результат, важный для продукта
tools/ocr/layout_probe.py проверил существующий фильтр на 20 новых синтетических документах с правым выравниванием сумм, другими заголовками и дополнительными строками: четыре каждого из пяти типов. 0/20 прошли фильтр, включая все четыре положительных примера. 0 ошибочных допусков здесь обусловлены полным отказом, а не высокой точностью. Это блокирует использование прежнего фильтра как рабочего парсера. Нужен разбор пространственных блоков, вариантов меток и контролируемое извлечение полей; не снижать порог вслепую. Для воспроизведения python tools/ocr/layout_probe.py; зависимости как в первом OCR-эксперименте плюс локальный DejaVu Sans.

Для независимой оценки найден https://huggingface.co/datasets/cdek-ocr/receipt-ocr-ru — русские чеки с разметкой, 151 тестовый образец, MIT указан в карточке; также оговорено исследовательское назначение, разметка частично машинная, координаты не исправлены вручную. Требуется проверять эталонные поля и допустимость использования. Изображения не получены: текущая среда не разрешает прямую загрузку выбранного URL. На этом датасете тесты не выполнялись. Не коммитить фотографии чеков/личные данные.

## Реальная фотография: диагностическая проверка зрения
tools/vision/coins_probe.py использует локальный scikit-image data.coins() (24 монеты; источник https://scikit-image.org/docs/stable/api/skimage.data.html#skimage.data.coins). OpenCV HoughCircles, четыре варианта одной фотографии. 24 объекта при param2=20, но 22/21/12/7 на исходном фото при повышении порога до 25/30/35/40. При уменьшении освещения разброс 24/22/16/9/5. Это одна фотография, параметры подобраны на ней, совпадение количества не доказывает верную локализацию. Не независимый тест качества и не универсальная модель. Результаты и код сохранены для воспроизведения; изображение не включено в репозиторий. Следует оценить распознавание по примеру на независимых сценах с разметкой объектов, а не использовать Hough как общий детектор.
