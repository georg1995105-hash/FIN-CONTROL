# Сравнение моделей распознавания числовых полей, 26.11.2026

Реальный локальный запуск tools/ocr/number_probe.py, Tesseract 5.5.0, 48 синтетических вырезок (12 значений × 4 варианта). Суммы содержат похожие цифры, десятичный разделитель и ведущий ноль. Каждая вырезка распознавалась моделями rus, Cyrillic, eng; формат строго [0-9]{1,7}[,.][0-9]{2}, порог confidence 85. Затем измерено совпадение двух и трёх результатов. Это модели одного движка, не независимые архитектуры. Не измеряется локализация полей, семантика строк или точность на реальных документах.

| Метод | Принято из 48 | Ошибок среди принятых | Медиана одиночного вызова |
|---|---:|---:|---:|
| rus | 34 | 0 | 33 мс |
| Cyrillic | 38 | 0 | 90 мс |
| eng | 33 | 0 | 101 мс |
| rus + eng, совпадение | 30 | 0 | — |
| rus + Cyrillic + eng, совпадение | 27 | 0 | — |

Три модели не решают проблему распознаваемости: 21/48 вырезок отклонена при строгом совпадении; отсутствие ошибочных допусков на таком малом наборе не доказывает точность в эксплуатации. Cyrillic существенно тяжелее (29,25 МБ против 3,86 МБ rus), улучшает наклон, но ухудшает размытие. Не выбирать ни одну конфигурацию для коммерческого релиза по этим результатам. Порог не ослаблен. Исходники и JSON локального запуска имеют Git blob SHA 28801e8e0c48ac923076b5d6cdc16e4b5b039914 и 5d9a9fca02b92ef9c236f5b3d835bfc10aad89f2.

Проверка доступности: curl к huggingface.co и github.com завершился ошибкой DNS (code 6). PaddleOCR, paddlepaddle, ONNX Runtime и EasyOCR отсутствуют в локальной среде. Загрузка реального CDEK-набора не проведена. Официальные кандидаты: Cyrillic PP-OCRv3/v5 mobile recognition (https://huggingface.co/PaddlePaddle/cyrillic_PP-OCRv3_mobile_rec, https://huggingface.co/PaddlePaddle/cyrillic_PP-OCRv5_mobile_rec), сравнивать на одном эталоне; опубликованные разработчиком метрики не равны измерениям FIN CONTROL. Карточка v5 указывает Apache-2.0; проверять лицензии, хеши и Android-совместимость конкретных весов. Независимый набор CDEK (https://huggingface.co/datasets/cdek-ocr/receipt-ocr-ru) содержит 151 тестовый чек, но разметка частично машинная, bounding boxes не исправлялись вручную; пригоден для исследования, не заменяет вручную проверенный эталон. Для всех реальных документов хранить только агрегированные метрики; не коммитить изображения или значения.

Следующее инженерное решение: отдельный одноразовый эксперимент на GitHub-hosted CPU runner с официальными моделями, не платный AI API. До независимой проверки не объявлять OCR или технологический этап готовым.
