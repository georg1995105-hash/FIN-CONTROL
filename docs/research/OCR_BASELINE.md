# Эксперимент OCR 26.11.2026

Локальная проверка Tesseract 5.5.0 (LSTM rus, 3 861 738 байт) на Linux x86_64, Pillow 12.3.0, NumPy 2.3.5. Tesseract и официальные модели распространяются по Apache-2.0: https://github.com/tesseract-ocr/tesseract и https://github.com/tesseract-ocr/tessdata_fast. Происхождение и лицензии фактических файлов Android-сборки ещё подлежат проверке; модели в Git не добавлены. Воспроизведение: установить Tesseract и русскую модель, Noto Sans, Pillow/NumPy; запустить python tools/ocr/ocr_benchmark.py. JSON фиксирует хеши модели и шрифта. Тест использует синтетические изображения, не пользовательские документы.

25 исходных образцов (по пять каждого типа), те же 25 после предобработки и дополнительные 25 с другими суммами, размером шрифта и параметрами искажений. Поля: товар, скидка, итог. Кандидат — все три поля найдены ровно один раз, формат суммы и уверенность >=85. Кандидат НЕ означает подтверждённую достоверность документа и не разрешает автоматическое финансовое заключение. OCR-уверенность не калибрована.

| Набор | Точные поля из 75 | Кандидаты из 25 | Ошибочные кандидаты | Медиана Linux |
|---|---:|---:|---:|---:|
| Исходный | 57 | 11 | 0 | 48 мс |
| Коррекция наклона + масштаб | 70 | 19 | 0 | 81 мс |
| Дополнительный набор | 65 | 15 | 0 | 74 мс |

Обрезанные образцы всегда отклонены, сильное размытие дополнительного набора — 5 отказов из 5. Указанные 75 полей включают заведомо отсутствующий итог в пяти обрезанных образцах. На 40 необрезанных снимках двух наборов после обработки — 34 кандидата, 6 отказов, ни одного неверного кандидата; статистически недостаточно для гарантий. Медиана включает подготовку, сохранение и запуск CLI; Linux не равен Android. RSS в JSON — максимумы, сообщаемые getrusage (возможна наследованная память fork); не размер модели в RAM и не измерение на устройстве.

Решение: сохранить Tesseract как кандидата для дальнейшего сравнения, не утверждать production-движок. Нужны реальные обезличенные разнообразные чеки и счета, разные раскладки строк, дубли, отдельные и уже включённые скидки, неизвестные форматы, проверки цен/количеств, оценка ошибок на независимых данных и замеры на ARM. Предобработка доказала пользу только на этом синтетическом наборе. Не снижать порог для достижения красивой статистики. Не переносить жестко заданные три метки в пользовательский OCR как универсальный парсер.
